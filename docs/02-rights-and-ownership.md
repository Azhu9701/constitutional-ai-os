# Rights and Ownership

AI systems often collapse several different relationships into one vague concept: "access."

That is insufficient.

## Resource relationships

A constitution may need to distinguish:

- **owner** — holds recognized ownership interest;
- **custodian** — holds a resource on another's behalf;
- **controller** — can decide how the resource is used;
- **operator** — can perform actions with it;
- **beneficiary** — is intended to receive benefit;
- **subject** — person or entity the data or action concerns;
- **licensee** — may use under defined terms.

One actor may occupy several roles.

## Rights are not capabilities

A **capability** says what an agent can currently do.

A **right** expresses a rule about what should be permitted, protected, required, or reviewable.

Example:

```text
Capability:
agent X has a token that can read dataset Y.

Constitutional question:
does agent X have legitimate authority to use dataset Y for this purpose?
```

Technical capability must not be treated as automatic legitimacy.

## Minimal right rule

A useful rule contains:

```text
subject
action
resource
effect
conditions
authority
justification
appeal / override path
```

## Collective resources

The model must not assume every resource is privately owned by one individual.

The schema should be able to represent:

- individual ownership;
- organizational ownership;
- joint ownership;
- collective ownership;
- public or commons resources;
- custodial resources;
- unowned / disputed resources.

The project can therefore compare constitutional models without forcing them into one ownership theory.
